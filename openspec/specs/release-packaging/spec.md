# Release Packaging Specification

## Purpose

为 macOS 发行包提供可重复、架构明确且可证明包含当前源码的构建流程，杜绝旧 `out/` 目录被误当成新产物。

## Requirements

### Requirement: 架构包必须替换同名旧输出
系统 SHALL 在构建指定 macOS 架构时替换对应的既有 `.app` 输出，而不得静默复用或跳过旧目录。构建失败时，系统 MUST 返回非零结果，且不得将旧包报告为本次构建成功的结果。

#### Scenario: 目标架构存在旧应用包
- **WHEN** arm64 或 x64 的目标输出目录在构建前已存在
- **THEN** 构建流程替换该架构的旧应用包
- **AND** 后续验证只针对新生成的包执行

#### Scenario: 打包过程失败
- **WHEN** 打包器未能完成指定架构的应用包
- **THEN** 发布命令以失败状态结束
- **AND** 不输出“构建完成”或可发布的成功结论

### Requirement: macOS 发布命令必须明确架构范围
系统 SHALL 提供单独构建 arm64、x64 以及全部受支持 macOS 架构的命令。每个命令 MUST 在命令名或输出中明确其架构范围，避免由运行机器架构隐式决定发布内容。

#### Scenario: 仅构建 Apple Silicon 包
- **WHEN** 发布者执行 arm64 构建命令
- **THEN** 系统只生成并验证 arm64 应用包
- **AND** 不把已有 x64 包冒充为本次输出

#### Scenario: 构建完整 macOS 发布集
- **WHEN** 发布者执行 macOS 发布构建命令
- **THEN** 系统分别生成并验证 arm64 与 x64 应用包
- **AND** 任一架构失败时整个命令失败

### Requirement: 发布包必须通过包内源码验证
系统 SHALL 在每个成功的架构打包步骤后验证目标 `.app` 的 `app.asar` 存在，并验证其受支持生产源码集合与当前工作区对应内容一致。验证失败 MUST 使该发布命令失败，并指明目标架构和不匹配原因。

#### Scenario: 包内源码是当前版本
- **WHEN** 指定架构的应用包刚由当前工作区成功生成
- **THEN** 验证通过并明确报告已验证的架构与应用路径

#### Scenario: 应用包来自旧构建
- **WHEN** 目标 `app.asar` 缺失、无法读取或包含与当前工作区不一致的生产源码
- **THEN** 验证失败并拒绝将该应用包作为当前发布产物
