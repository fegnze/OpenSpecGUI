## Why

OpenSpec GUI 已能提示任务完成和待归档，但用户仍需离开界面才能检查规范同步并完成归档。允许用户直接审阅和执行确定的 OpenSpec 管理操作，可以形成完整的归档闭环，同时保持软件对 AI Agent、会话历史和模型服务的独立性。

## What Changes

- 将桌面工作台的产品边界从仅展示内容扩展为支持用户主动触发、结果可审阅的命名管理操作，首期只实现单个活跃 Change 的归档。
- 在活跃 Change 详情提供“归档”入口，依次呈现任务及产物状态、规范校验、正式规范的文件差异和归档目标，再由用户确认执行；任务完成提示不构成实现验收。
- 无增量规范或正式规范已同步时只移动 Change；存在可按 CLI 规则处理的增量时，预览同步结果并在确认后同步与归档。无法确定合并结果或校验失败时保留原文件，显示具体问题。
- 使用兼容的 OpenSpec CLI 计算归档结果，GUI 不接入模型、不读取 Agent 会话，也不自行推断需求或修改实现代码。CLI 不可用或无法提供可靠预览时继续支持现有浏览能力。
- 将确认绑定到预览的项目、文件内容、归档目标和操作结果；文件或项目变化使预览失效，重复提交不会重复归档，失败时明确实际文件状态。
- 首期不提供批量归档、忽略校验、跳过尚未同步的规范、撤销已完成归档、任务勾选或新建变更等额外写操作。

## Capabilities

### New Capabilities

- `change-archive`: 单个 Change 的归档预检、规范差异预览、明确确认、受限写入、并发变更检测及失败恢复。

### Modified Capabilities

- `desktop-workbench`: 增加受控归档入口，保持项目隔离与命名 IPC 边界，并明确 CLI 能力不足时的浏览降级和归档能力限制。

## Impact

- `src/core/openspec-cli.js` 及新增归档模块：CLI 能力检查、隔离预演、归档计划和受限提交；不将现有状态查询的五秒超时直接套用到归档。
- `src/main/workbench-service.js`、`src/main/ipc.js`、`src/preload/index.js`：绑定当前项目和 revision 的预检、确认及取消接口，以及主进程持有的计划生命周期。
- `src/renderer/app.js`、`src/renderer/styles.css`：详情操作、检查与 diff 预览、警告确认、进行中和结果反馈、成功后的归档导航。
- 聚焦归档、IPC、项目切换、文件并发和故障恢复的自动化测试，以及真实 Electron 操作与界面验证。
- 更新 README 和桌面工作台 Purpose，移除笼统的“只读”定位。写入被导入项目是新增的显式能力，既有浏览流程仍可独立使用；不新增 Agent、网络服务或 AI SDK 依赖。
