## Context

当前渲染层已经通过 `bridge.clipboard.write` 使用受控 IPC 写入系统剪贴板，文档详情中的“复制路径”已经验证这条链路。提案状态卡、筛选表格行和归档列表行目前各自以整块 `<button>` 渲染，因此不能直接在其中嵌套第二个复制按钮。参见 `proposal.md` 与 `specs/desktop-workbench/spec.md`。

界面属于高密度桌面工作台。本次采用现有原生 CSS、Lucide 图标、语义色和 3-5px 圆角体系，设计参数为低变化、低动效和高密度，不引入新的设计系统或动画依赖。

## Goals / Non-Goals

**Goals:**

- 在活跃提案卡片、筛选表格、归档列表和提案详情中提供一致的一键复制机器名操作。
- 保留整张卡片或整行打开提案的既有交互热区，并使复制与打开拥有独立的键盘焦点和辅助技术名称。
- 在宽桌面、紧凑桌面和最小窗口下保持标题、机器名、状态、进度及复制按钮不重叠。
- 复用现有剪贴板 IPC、安全边界、图标与 toast 反馈。

**Non-Goals:**

- 不复制提案展示标题、文件路径或整份 proposal 内容。
- 不增加上下文菜单、批量复制、复制格式选择或键盘全局快捷键。
- 不改变提案状态计算、列表排序、筛选、路由或归档流程。
- 不为正式规范条目增加复制提案名按钮。

## Decisions

### 1. 复制值固定为提案机器名

复制操作使用实体的 `id`，例如 `add-copy-proposal-name`。该值可直接用于 OpenSpec CLI，也不会因 proposal 标题文案变化而失效。

备选方案是复制展示标题，但标题可能包含空格、中英文标点且不能直接用于命令，因此不采用。

### 2. 打开与复制使用同级按钮

提案卡片和列表行改为语义容器，容器内放置覆盖主要内容区的“打开提案”按钮与同级的图标复制按钮。视觉容器继续承担背景、边框、状态色和 hover 层级，打开按钮继续覆盖原有主要点击区域，复制按钮拥有独立焦点顺序。

事件委托优先处理 `data-action="copy-proposal-name"`，复制按钮携带经过转义的 `data-proposal-name`。复制事件完成后立即返回，确保不会落入实体导航处理。

备选方案是在现有整块 `<button>` 中嵌套复制按钮，但这会产生无效 HTML、混乱的键盘行为和浏览器不一致事件，因此不采用。仅让机器名文本可选择也无法满足一键复制和触控操作。

### 3. 使用紧凑图标按钮与双层反馈

按钮使用项目已有 `copy` 图标、现有 `icon-button` 交互语言和可见焦点环。默认 tooltip 为“复制提案名”，`aria-label` 包含具体机器名，例如“复制提案名 modern-console”。

写入成功后显示“提案名已复制”toast，并在当前按钮上短暂切换为 `check` 图标和“已复制”可访问状态；写入失败显示“无法访问剪贴板”，按钮保持可重试。短暂图标切换只表达操作结果，遵守减少动态效果偏好，不引入位移或自动动画。

仅显示 toast 的方案实现更少，但远离视线中心时确认感较弱；按钮局部反馈与 toast 组合能同时服务视觉定位和全局确认。

### 4. 复用现有剪贴板边界

渲染层新增 `copyProposalName(name, button)` 辅助函数，并继续调用 `bridge.clipboard.write(name)`。主进程、preload API 和允许的 IPC 通道不变，复制文本仍受现有非空字符串与 8192 字符限制。

直接调用 `navigator.clipboard` 会绕过项目现有安全测试和 Electron 权限边界，因此不采用。

### 5. 各界面使用同一生成器和稳定布局槽位

渲染层提供统一的提案复制按钮 HTML 生成器，状态卡、筛选行、归档行和两种提案详情复用同一数据属性、tooltip 与可访问名称。CSS 为复制按钮预留固定尺寸槽位，标题和机器名使用 `min-width: 0`、省略或换行规则，避免按钮出现时挤压主要内容。

归档列表仅在实体类型为 `archive` 时显示复制按钮，正式规范列表保持现状。搜索结果不属于本次主要提案入口，暂不增加操作，避免结果行操作密度过高。

## Risks / Trade-offs

- [整块按钮拆为同级操作后 hover/focus 样式可能分裂] -> 将卡片或行容器作为视觉状态载体，并使用 `:has()` 或聚焦类统一边框与背景反馈，测试鼠标和键盘两条路径。
- [复制按钮占用紧凑窗口空间] -> 使用固定 30-36px 图标槽位，在 1279px 与 959px 断点显式调整表格、卡片和归档行网格，并运行文本适配与无溢出断言。
- [事件委托同时匹配操作与实体] -> 在实体导航前优先处理复制 action，复制分支立即返回，并以 E2E 断言路由、筛选和滚动位置不变。
- [局部成功状态的计时器遇到重新渲染] -> 状态恢复前先检查按钮仍连接到文档；页面已重绘时直接结束，不持有全局 UI 状态。
- [视觉基线因新增操作发生预期变化] -> 更新受影响的执行台、筛选列表、详情和归档截图，并逐张审阅宽、紧凑和最小窗口布局。

## Migration Plan

1. 先加入统一复制辅助函数和按钮生成器，再逐个迁移提案入口的标记结构与样式。
2. 运行语法、单元、安全、Electron E2E、可访问性和视觉回归测试。
3. 如需回滚，恢复提案卡片与列表行为单一按钮，并移除复制生成器及相关样式；IPC 层无需回滚。
