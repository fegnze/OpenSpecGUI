## Context

当前工作台由 `.app-shell` 网格承载，左侧 `.sidebar` 贴合窗口边缘并占满高度，顶部通过约 46px 留白避让 macOS 原生窗口控制区。右侧工作区独立滚动，侧栏和工具栏保留拖拽区域。现有 960px 断点会将侧栏收缩为图标优先导航。

用户已确认将左侧边栏改为圆角悬浮框的预览方向。此次为保留式视觉演进：不改变导航信息架构、项目切换、路由、快捷键或 IPC 行为。

## Goals / Non-Goals

### Goals

- 在宽桌面窗口中让贴边侧栏与圆角工作区形成统一、克制的双面板层级。
- 延续现有配色、导航密度、原生窗口控制区避让和拖拽行为。
- 保持工作区无额外卡片边框，避免将整个应用改造成厚重的双卡片布局。
- 在紧凑与最小桌面窗口中保留图标优先的侧栏，避免压缩正文与主要操作。

### Non-Goals

- 不修改导航项、项目选择器、文案、路由或业务交互。
- 不引入透明毛玻璃、装饰性动效、额外依赖或新的组件层级。
- 不调整 OpenSpec 文件读取、状态计算、IPC 或打包行为。

## Decisions

### 1. 宽桌面采用“贴边侧栏，圆角工作区”的双面板外壳

宽桌面中侧栏在窗口左、上、下三条外沿均为 0px，右侧保留 6px 间距；侧栏四角采用 14px 圆角、低对比细边框与阴影。主工作区在四角使用相同的 14px 圆角；仅在工作区右侧保留 4px 画布露边以完整显示右侧圆角。工作区不增加额外卡片边框，避免重现厚重的双卡描边。

工作区顶栏显式采用顶部两个 14px 圆角，工作区用相同轮廓裁剪其粘性子内容，确保顶栏在初始与滚动状态都不会覆盖右侧圆角。

理由：用户确认侧栏与右侧内容应使用一致的圆角语言，侧栏外沿收敛为 0px。6px 面板间距提供明确的呼吸感，且无工作区边框可避免出现此前厚重的整窗卡片感。

### 2. 保留原生窗口控制区和拖拽边界

侧栏顶部内容仍保留不小于现有值的安全留白，`.sidebar` 和 `.toolbar` 的拖拽语义继续存在，交互控件维持非拖拽区域。另设一个仅覆盖左上标题栏安全带的独立拖拽层，它从原生窗口控制按钮右侧开始，右边界与侧栏对齐，不得进入工作区交互范围。贴边布局不得覆盖或阻挡 macOS 原生窗口控制区。

理由：该应用使用 `hiddenInset` 标题栏，视觉更新不能牺牲窗口控制或拖动体验。

### 3. 使用现有断点做紧凑回退

浮动面板仅在现有宽桌面范围内生效。达到当前紧凑断点后，外壳留白、阴影和大圆角将收紧或取消，侧栏继续沿用图标优先布局；最小窗口不得出现横向溢出或控件遮挡。

理由：保留 960px 以下的内容宽度比在窄窗口中维持视觉悬浮更重要。

### 4. 采用克制且一致的视觉令牌

为外壳间距、面板圆角、边框和阴影建立或复用少量 CSS 自定义属性。圆角使用同一软圆角尺度，阴影使用低不透明度的中性色调，不增加渐变、发光、顶部状态装饰条或透明材质。

理由：工作台当前是高信息密度的工具界面。新的表面层级应是可感知的布局信号，而不是抢占注意力的装饰。

## Risks / Trade-offs

- 相邻面板的圆角会在顶部和底部形成可见的画布留白，右侧工作区需要 4px 露边以显示圆角；需在 960px 到 1280px 的窗口宽度验证项目选择器、导航标签和正文不会过度拥挤，且侧栏与工作区之间的 6px 间距保持克制。
- 阴影和圆角可能截断焦点轮廓或在短窗口压缩底部状态，需要检查键盘焦点和最小窗口高度。
- 原生窗口控制区由操作系统叠加，必须在真实 macOS 窗口中确认顶部安全留白和拖拽区域没有回归。

## Migration Plan

这是一项纯渲染样式变更，无需数据迁移或发布开关。若出现窗口控制、紧凑断点或视觉回归，可回退外壳和侧栏样式规则，不影响用户数据、项目配置或 OpenSpec 内容。

## Open Questions

无。预览方向、保留范围和紧凑窗口策略已经确认。
