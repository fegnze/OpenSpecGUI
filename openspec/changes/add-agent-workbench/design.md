## Context

工作台已支持 Git 项目、OpenSpec 工作区、能力管理和受限 IPC。已实现的能力登记支持本机添加和全局绑定。本次调整将收录权交给维护者，要求成员逐项目选用，并补齐 macOS 整包更新。

## Goals / Non-Goals

**Goals:** 保持同一个桌面应用和项目登记入口。让没有 OpenSpec 的仓库也能配置 Agent，并可在真实宿主中验证项目范围与钩子效果。保留已有项目数据和归档保护。

**Non-Goals:** 跨团队运营、成员端自建目录、独立能力包发布服务、替代宿主权限、代理 Agent 会话、远程托管执行适配和新的 OpenSpec 生命周期。首版以当前团队使用的 macOS 本机环境验收。

## Decisions

### 1. 先登记项目，再识别 OpenSpec

项目注册表仍以真实路径识别检出的项目。Git worktree 通过 Git 元数据识别，既有非 Git OpenSpec 项目继续可登记。仓库根和 OpenSpec 根分别校验，`openspec/` 的可用状态独立探测。普通项目保有已选项目身份，OpenSpec 快照为空。主进程拒绝此类项目上的文档、专项和归档请求，切换时让旧的预览和异步响应失效。

侧栏按项目级「Agent 配置」「OpenSpec」和底部「全局」布局。OpenSpec 入口沿用旧路由，普通项目进入能力绑定。项目页面的恢复按项目 ID 记录。全局页面的上下文与项目选择独立。这个方案延续项目注册和切换行为，同时把 OpenSpec 可用性从项目身份中分离。

### 2. 所有项目共用随应用发布的能力目录

维护者在工作台仓库收录四类能力，为每项登记稳定 ID、类别、来源、版本和所需权限。Skills 和规则保留版本化内容，Tools 标明脚本、原生宿主工具或 MCP 工具的来源，MCP 描述声明连接方式。服务端运行版本以实际可核验的信息为准。能力文件、目录和内置适配器一起构建，成员更新应用即可看到维护者新收录的条目和版本。

「能力绑定」展示当前应用版本的完整目录。两个项目可见的条目和版本相同，各项目分别记录是否选用、采用版本、目标宿主和项目参数。成员从项目根或 worktree 的真实路径进入配置。尚未选择项目时提示先选择或添加项目，再进入能力绑定。没有本机默认绑定、全局能力绑定或跨项目继承。成员可编辑的本机显示名按稳定 ID 保存，两个项目看到同一别名。宿主接入、个人登录和钥匙串凭据可留在本机，只有相应项目明确选用后才可使用该能力。

绑定与运行回执保存在用户数据目录，宿主配置按实际支持范围写入。如果宿主只能在所有项目启用某能力，且无法可靠隔离，界面在该项目报告限制。应用更新保留已有项目的固定版本与配置。成员可在一个 worktree 试用新版本，再决定是否调整另一项目。

首批逐项提供飞书缺陷和 WTC 的 git-commit 两项 Skill、cv-test1 HTTP MCP、飞书文档与 Google Drive 两项 Tool。基础规范从 WTC 提取可移植路径、任务范围和变更验证。文档认证复用桌面应用的系统浏览器与加密存储。连接验证读取指定飞书文档的基本信息或 Drive 文件元数据，并记录验证时间。飞书缺陷 Skill 的个人 Meegle 身份和工作树字段映射由其独立入口管理。

在 Agent 会话中，DeepSeek Harness 插件提供原生文档工具，Codex 和 Claude Code 从会话启动钩子获得可通过 shell 调用的工作台命令。入口在每次执行时根据实际工作树、宿主和固定版本核对绑定，再交给本机工作台使用对应的个人授权。飞书 1.0/2.0 提供新版文档正文读取。选用 3.0 后可另行授权读取知识库节点及创建评论，按用户请求创建全文评论或锚定文末的批注。Drive 继续使用文件元数据只读授权，支持筛选、翻页及按 ID 查询。

文末批注从文档树尾部按需定位最后一个有内容的块，跳过空白段落。收到飞书的创建回执后只读核对块上的评论 ID。已经写入的批注可通过同一读取工具复查原块、当前文末及块链接。客户端中的展示状态由成员在文档中确认。

### 3. 用薄适配器接入宿主，钩子由宿主直接执行

主进程提供明确命名的发现、预览、应用、解除和诊断操作。Codex 与 Claude Code 的适配器分别识别可用版本、原生配置和信任条件。应用只修改获确认的宿主条目。先准备版本内容，再写配置并记录前后摘要。中断可按记录恢复，发生外部修改时保留现场供成员审阅。解除时先取消引用，再清理无人使用的内容。

安装时把钩子程序部署到稳定的用户级目录。配套入口根据宿主事件提供的工作目录解析真实项目，用本机绑定计算适用规则。`SessionStart` 提供短诊断和规则入口，已经可以可靠匹配的检查由同步 `PreToolUse` 或受控工具执行。元数据由适配器提供。桌面进程或渲染页面仅显示结果，关闭应用不影响原生入口。

验证使用真实宿主、一次性探针标识和无害操作结果。每条回执包含项目、宿主、事件、规则版本、决策和原因。未触发、等待信任、超时和明确拒绝分别报告。校验通过后仍由宿主执行其权限判断。规则要求故障时停止的操作，由受控工具本身执行检查。各原生钩子的覆盖范围以适配器在支持版本上的验证为准。

### 4. 复用归档预检和现有项目工作流

桌面和受控 Agent 入口共用只读预检。它核对项目、Change、项目锁定的 CLI 和项目指定的规范同步要求，并在快照中运行官方 OPSX 严格校验和归档命令。桌面呈现差异，Agent 呈现相同的差异、警告和审阅指纹。确认后，两个入口以同一工作树写入锁复核项目规则和输入，只提交所审阅的官方 CLI 结果，沿用桌面端的失败恢复流程。工作台读取当前工作树选用的归档规则，并适配 WorldTourCasino 的锁定版本、中文工件检查和先同步要求。

### 5. 通过稳定的 HTTPS 入口分发整包更新

维护者为每个版本生成架构明确的 macOS 完整安装包和版本元数据。元数据列出应用版本、架构、对应包地址、校验摘要与更新说明。沿用包内源码一致性校验，发行包使用团队的 Developer ID 签名并完成公证。每个架构在固定的 HTTPS 地址提供版本索引 `RELEASES.json`，成员端只读，发布流程有写权限。可使用现有静态站点或对象存储，具体 URL 和供应商待选。

发布时先上传带版本号的完整包，在分发地址核对架构、可下载性和摘要，最后发布新版索引。首次安装支持更新的签名版后，客户端在后台检查适配本机架构的版本，成员也可手动检查。下载后校验完整性和发布者身份，显示更新说明并提示成员重启。下载中断、签名不可信或校验不匹配时继续使用原版本，允许重试。新目录随新客户端生效，已有项目的选用记录继续生效。

## Risks / Trade-offs

- 宿主版本、工具事件和信任条件存在差异。按宿主记录支持范围和已验证证据，在界面展示缺失的前置条件。
- 部分钩子超时后宿主会继续执行。对必须阻断的写入保留受控入口预检，并在验收中单独验证错误和超时路径。
- 用户可能并行编辑宿主配置。应用前重查文件摘要，按安装台账逐步恢复，仅在仍匹配本次写入时自动回退。
- OpenSpec 根被移动或仓库切换时，旧结果可能过期。以项目 ID、工作区版本和归档输入指纹校验读取与执行。

## Migration Plan

1. 从现有用户数据读取项目。保留项目 ID，按需把旧注册记录迁移到包含可选 OpenSpec 状态的结构，并保留可恢复备份。Agent Workbench 保留原应用标识、用户数据和系统凭据存储身份。改名后首次手动启动新版时，仅将已登记且匹配安装台账的宿主入口更新到当前应用位置，沿用已有的项目及宿主绑定。
2. 迁移时保留明确属于某个项目的绑定、来源快照、别名和个人授权。旧全局绑定及仅在本机登记的自定义能力保留可恢复记录，提示成员按项目确认，缺少团队目录条目的由维护者收录。新项目和其他工作树不会自动继承旧记录。
3. 成员从预览确认每个宿主的接入动作。回退使本机能力回到先前版本或解除已登记的接入。原有项目与宿主配置按文件及所有权保留。
4. 用 WTC 和普通 Git 仓库验证项目范围，用无害夹具验证拒绝和放行。归档只在测试夹具执行实际写入。团队分发前核对 macOS 签名、公证和安装验证。
