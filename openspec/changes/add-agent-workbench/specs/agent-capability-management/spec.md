## Purpose

团队维护者在仓库收录四类 Agent 能力，随工作台发布。成员从同一份目录了解每项能力的来源和版本，在指定工作树及宿主中启用并配置所需条目，核查实际生效状态。

## ADDED Requirements

### Requirement: 从维护者仓库发布四类能力目录
团队维护者 SHALL 在仓库中收录 Skills、MCP、Tools 和基础规范，为每项能力指定稳定 ID、类别、来源、版本信息及依赖。工作台 MUST 以本应用版本所含的目录和能力定义为准。成员通过安装新版工作台获得维护者的变更，成员端 MUST NOT 提供从其他来源添加、替换或单独发布能力的操作。

#### Scenario: 在仓库中收录能力
- **WHEN** 维护者从各自来源收录一项 Skill、一条 MCP 连接、一项 Tool 和一份基础规范，并随新版工作台发布
- **THEN** 安装该版本的成员在各自项目中均能看到这四项能力及其来源，新收录条目初始均未启用

#### Scenario: 显示各类能力的版本与依赖
- **WHEN** 用户查看当前包收录的能力
- **THEN** 可固定版本的来源显示包中收录的版本或提交，远程 MCP 显示连接及验证状态且只展示服务可确认的运行版本
- **AND** Tools 区分独立脚本或命令、宿主自带工具以及由 MCP 连接提供的工具，显示各自来源或所属连接

### Requirement: 明确能力的启用范围
系统 SHALL 向所有已注册项目展示同一版本的完整能力目录。启用、停用及项目配置 MUST 以规范化后的实际项目或 worktree 根和目标宿主为范围。系统 MUST NOT 提供本机默认或全局能力绑定。成员 SHALL 能区分目录已收录、项目已启用和宿主已验证三种状态。项目正式规范 SHALL 继续从当前 OpenSpec 工作区读取。

#### Scenario: 在项目之间切换
- **WHEN** 成员在工作树 A 的 Codex 中启用一项能力，再切到同一仓库的工作树 B 或 A 的 Claude Code
- **THEN** 各处均可查看该条目，只有 A 的 Codex 显示本次启用和对应配置，其他工作树和宿主继续使用各自的选择

#### Scenario: 升级时遇到旧的全局能力绑定
- **WHEN** 成员升级工作台时，本机存在旧版本的全局启用记录
- **THEN** 系统不得把该记录作为任何现有或新建项目的默认值，也不得自动复制为项目绑定
- **AND** 该能力只有在当前工作树和宿主已有明确项目绑定，或成员主动启用后才能生效

#### Scenario: 宿主不支持项目范围
- **WHEN** 用户将能力限制在单个项目，但选定宿主只能以用户级范围发现该能力且无法可靠隔离
- **THEN** 系统说明该范围不支持并保留原接入状态，不将该条目提升为全局启用

#### Scenario: 有效规范出现冲突
- **WHEN** 当前工作树拟启用的基础规范和该项目正式规范包含不可同时满足的必需规则
- **THEN** 系统展示冲突及双方来源，等待用户解决后再应用变更

### Requirement: 按整包更新目录并审阅项目启用
工作台 SHALL 随发布包整体更新目录和能力定义。成员 SHALL 能查看当前包版本及条目来源、版本和权限，并在启用前审阅目标工作树、宿主与配置差异。系统 MUST 校验包所声明的来源及内容后再启用可执行能力。成员 SHALL 能解除选定的项目绑定。

#### Scenario: 成员安装新版工作台
- **WHEN** 新版工作台更新已有 Skill 并新增一个工具，成员完成工作台整包更新
- **THEN** 各项目显示同一新版目录，仍收录条目的既有项目选择及兼容配置按稳定 ID 保留，新工具在每个工作树和宿主中均未启用
- **AND** 已移出目录的条目不得继续作为当前包的有效能力

#### Scenario: 版本无法确认或来源内容不匹配
- **WHEN** 工作台更新包无法获取或内容与声明不符
- **THEN** 系统报告原因，保留此前成功安装的工作台及项目绑定，目录中不得混入未成功安装的版本

### Requirement: 本机保存绑定并委托宿主管理凭据
系统 SHALL 在本机保存已安装包的版本、项目与宿主绑定及个人设置。系统 MUST NOT 为本机绑定修改业务仓库中的跟踪文件。MCP 登录及凭据 SHALL 由宿主或系统凭据存储负责。本机账号身份或已有授权 MUST NOT 代替当前工作树及宿主的显式启用。

#### Scenario: 需要账号登录的 MCP
- **WHEN** 已启用的 MCP 连接需要个人账号授权
- **THEN** 系统显示待登录并引导用户在宿主完成授权，工作台的设置及回执中不包含凭据，重启工作台后仍保留连接引用和绑定

#### Scenario: 授权并验证飞书文档连接
- **WHEN** 成员从已启用的飞书文档 Tool 2.0 发起连接授权
- **THEN** 工作台默认申请 `docx:document` 和 `offline_access`，并以飞书实际返回的 `docx:document` 确认文档读写授权
- **AND** 旧连接须经成员重新授权才能取得读写权限。验证连接时，工作台只读取指定文档的基本信息

#### Scenario: 授权 Google Drive 连接
- **WHEN** 成员从已启用的 Google Drive Tool 发起连接授权
- **THEN** 工作台申请文件元数据只读权限，使用文件元数据查询验证连接

#### Scenario: 升级飞书文档工具的授权
- **WHEN** 成员为某一工作树与宿主选用飞书 3.0，并继续使用已有授权
- **THEN** 工作台根据实际获授的范围保留可用操作，提示补充缺少的文档读写、知识库节点读取或评论创建权限
- **AND** 用户完成重新授权后，该工作树和宿主可使用新获授的操作，其他工作树和宿主的固定版本保持各自的能力范围

#### Scenario: 离开页面后重新授权
- **WHEN** 飞书或 Google Drive 的浏览器授权仍在等待，成员刷新工作台或切换页面后返回
- **THEN** 成员可直接重新授权。工作台可复用当前尝试的输入，也可使用成员修改后的输入，为该工作树、宿主和服务启动新的授权
- **AND** 迟到的旧回调无法写入新结果。成员可以取消等待，授权失败或超时后可立即重试，已有连接保留至新授权保存成功

### Requirement: 从 Agent 会话调用项目已选用的文档工具
工作台 MUST 在 DeepSeek Harness 的宿主工具接口提供文档工具，并向 Codex 和 Claude Code 会话提供通过 shell 调用的本机入口。每次执行 MUST 核对实际工作树、目标宿主和该服务的固定版本，只能使用对应绑定下的个人授权。文档服务的令牌和客户端密钥 MUST 留在工作台的凭据处理进程内。

#### Scenario: 读取飞书文档并按要求批注
- **WHEN** 在已选用飞书 3.0 的宿主中，成员要求读取可访问的 docx 或知识库中的新版文档，或明确要求在文末添加批注
- **THEN** Agent 可以调用工作台读取正文，或用评论工具把用户指定的文字锚定到文末并返回评论标识
- **AND** 目标位置无法锚定时说明原因，不改写正文或自动替换为全文评论

#### Scenario: 核对文末批注的位置与状态
- **WHEN** 成员要求添加文末批注，或提供已有回执中的块 ID 和评论 ID 核对位置
- **THEN** 工作台从文档末尾按需查找有内容的段落或媒体块，跳过空白段落，并提供可定位的块信息
- **AND** 创建成功的回执区分接口受理、块上的评论关联和客户端展示。对已有回执的核对只读取文档块，回读失败时不会重复写入

#### Scenario: 固定版本和缺失授权
- **WHEN** 会话固定在飞书 1.0 或 2.0，或所需的知识库或评论权限尚未授予
- **THEN** 已授权的 docx 正文读取仍可使用，超出该版本或实际授权范围的调用会说明应调整的绑定或授权

#### Scenario: 查看 Google Drive 元数据
- **WHEN** 当前工作树的目标宿主已选用并授权 Google Drive，成员要求列出文件或查看指定 ID 的元数据
- **THEN** Agent 可按名称前缀或文件夹查询、翻页或读取单个文件的元数据，使用已有的元数据只读权限

#### Scenario: 同一入口在另一工作树调用
- **WHEN** 相同的工具调用来自未绑定该服务的工作树或目标宿主，或会话启动后已解除绑定
- **THEN** 工作台拒绝调用，不载入或复用其他工作树或宿主的个人授权

### Requirement: 管理列表和按需设置
系统 SHALL 在项目「能力绑定」中以紧凑列表展示包内完整目录及当前工作树和宿主的启用状态。成员 SHALL 在此页查看条目的类别、版本、来源及依赖，按需启用、配置或停用。

#### Scenario: 对照同一宿主的能力
- **WHEN** 成员在当前项目的「能力绑定」筛选类别或名称
- **THEN** 成员能对照条目的版本、来源和宿主支持状态，并对支持当前宿主的选中项启用、配置或停用

#### Scenario: 从项目绑定修改本机显示名称
- **WHEN** 成员在「能力绑定」选中包中收录的一项能力，编辑本机显示别名并保存
- **THEN** 本机各项目与宿主的列表、搜索和详情均使用新名称，重启后仍可见
- **AND** 原能力 ID 继续标识版本、绑定及连接，MCP 命令模板继续引用原服务标识，目录定义及各项目的启用状态不受改名影响

#### Scenario: 在填写连接设置时重命名
- **WHEN** 成员在连接设置中修改显示名称，或取消本次改名
- **THEN** 成员可继续填写同一表单，已输入的设置仍保留在表单中，保存令牌仍需使用连接设置自己的操作

### Requirement: 工作台管理飞书缺陷的启动前设置
系统 SHALL 按当前实际工作树保存飞书缺陷的项目键、工作项、默认来源、字段映射、工程交付入口及消息配置。系统 SHALL 通过厂商支持的入口检查或引导各成员的个人授权，并分别展示项目账号、消息应用和收件人映射的实际状态。

#### Scenario: 首次配置后使用 Skill
- **WHEN** 成员在当前工作树与宿主启用飞书缺陷 Skill，保存项目配置，并从该工作树使用支持工作台配置的 Skill
- **THEN** Skill 能找到该工作树的本机绑定，并继续在启动任务时核对本轮目标、处理模式、工程与 QA 群

#### Scenario: 调整已有配置
- **WHEN** 成员关联已有绑定并修改表单字段
- **THEN** 工作台将修改保存为本机配置，保留原绑定中的路由、交付配置与路径语义，在外部文件或项目已改变时要求重新读取

#### Scenario: 查看本人的授权情况
- **WHEN** 成员主动检查账号或发起授权
- **THEN** 系统展示厂商工具可核验的身份与所需操作，等待本人在官方流程完成登录，并将未核验的消息权限与身份映射标为待核验
