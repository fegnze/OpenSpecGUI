## Purpose

为本机 Codex 和 Claude Code 提供可审阅、可恢复的原生接入，并用真实会话中的触发回执说明检查是否生效、适用哪个项目以及哪些故障会限制阻断能力。

## ADDED Requirements

### Requirement: 检测并预览宿主原生接入
系统 SHALL 在「宿主接入」中显示本机 Codex 与 Claude Code 的检测结果、版本和支持范围，并在用户确认前展示将修改的配置项、适用范围及权限。本机宿主安装及其公共入口 SHALL 独立于各实际工作树和宿主的能力绑定。系统 MUST 使用宿主支持的原生注册入口并保留宿主的信任、登录及权限判断。

#### Scenario: 预览接入受支持的宿主
- **WHEN** 用户选择受支持的宿主并预览其本机接入
- **THEN** 系统显示将安装的宿主入口及所需配置，在用户确认前不写入
- **AND** 宿主要求信任、登录或重新加载时，系统展示需在该宿主完成的操作

#### Scenario: 宿主缺失或版本不支持所选入口
- **WHEN** 宿主未安装、无法识别版本或不支持所选配置入口
- **THEN** 系统说明异常及适用的处理步骤，不写入未经验证的配置

#### Scenario: 本机完成安装后打开尚未启用能力的工作树
- **WHEN** 成员已在本机安装 Codex 入口并登录个人账号，随后在没有对应能力绑定的工作树启动 Codex
- **THEN** 宿主接入状态显示已安装，工作台不会向该会话提供任何仅因已收录、已有登录或在另一工作树启用的能力

### Requirement: 可逆地修改受工作台管理的宿主配置
系统 SHALL 只修改用户已确认且由工作台管理的接入项，并保留应用、回退和解除接入所需的本机记录。系统 MUST 保留宿主的手工配置及其他仍有引用的安装项。

#### Scenario: 重复接入与解除接入
- **WHEN** 用户对同一宿主和范围重复应用一条接入，再解除该接入
- **THEN** 重复应用不产生重复注册，解除后只移除与该接入对应且不再被引用的条目，已有手工配置依然保留

#### Scenario: 写入中断或遇到外部修改
- **WHEN** 一次接入在完成前中断，或用户在接入后手工修改了拟回退的条目
- **THEN** 系统能识别已经生效和尚未生效的写入，恢复时只回退仍与本次写入匹配的条目
- **AND** 若遇到外部修改，系统保留该修改，显示冲突并提供继续处理所需的信息

### Requirement: 宿主独立运行钩子并解析实际项目
系统 SHALL 允许宿主在工作台关闭后运行已接入的检查。检查 MUST 根据原生事件提供的实际工作目录解析仓库和 worktree，并按已应用的项目绑定、事件类型和检查版本确定适用规则。工作目录缺失或范围含糊时，系统 MUST 按检查项的已声明策略处理并记录原因。

#### Scenario: 关闭工作台后在真实会话运行检查
- **WHEN** 已接入的 Codex 或 Claude Code 在工作台关闭后以注册项目为工作目录启动新会话，或发起已覆盖的工具调用
- **THEN** 宿主通过原生事件执行当前检查，产生本机回执
- **AND** 校验通过的操作继续接受宿主自身的权限判断

#### Scenario: 工作目录指向另一项目或无法确定
- **WHEN** 事件工作目录指向另一个项目、没有提供，或无法唯一确定项目范围
- **THEN** 检查不将其他项目的专属策略视为已匹配，回执记录实际解析或适用策略的结果

### Requirement: 从真实宿主会话验证接入
系统 SHALL 区分已挂载、待信任、待验证、已验证和不支持或异常。系统 MUST 仅以真实宿主会话的回执作为项目检查已验证的证据，且回执必须匹配实际工作树、目标宿主及其版本和当前检查版本。系统 SHALL 在对应项目的「钩子记录」显示最少必要的事件时间、宿主、检查项、结果和原因，并在宿主或检查版本变化后提示重新验证。

#### Scenario: 仅完成注册或模拟验证
- **WHEN** 宿主配置已写入，但没有收到匹配的真实会话回执
- **THEN** 系统显示待信任或待验证等实际状态，不能以配置存在、模拟执行或旧版本回执标记已验证

#### Scenario: 核对真实工具调用的实际结果
- **WHEN** 用户分别在已接入的 Codex 与 Claude Code 真实会话中，以一次性验证标识发起一条应放行和一条应拒绝的无害工具调用
- **THEN** 团队可通过相应回执核对调用及其实际结果，并在对应项目中看到检查放行和明确拒绝的记录

#### Scenario: 已登记宿主在未绑定能力的项目触发钩子
- **WHEN** 当前工作树与宿主的上下文事件和工具检查事件都产生了回执，两项均因没有生效绑定而跳过
- **THEN** 「宿主接入」显示两类钩子已触发、该项目跳过检查的原因和最近触发时间
- **AND** 页面打开时使用现存匹配回执，有新回执时自动更新；仅观察到一类事件或出现执行错误时分别显示实际情况

### Requirement: 说明钩子覆盖范围和故障语义
系统 SHALL 为每个宿主与检查组合展示实际覆盖的事件、失败行为和是否具备阻断能力。项目记录 MUST 区分检查明确拒绝、钩子超时、执行异常和未观察到预期回执。对必须失败即停止的受控操作，受控入口 MUST 自行完成必要校验，不能以钩子注册或回执缺失推定校验通过。

#### Scenario: 钩子明确拒绝
- **WHEN** 已覆盖的工具调用未通过同步检查，且宿主支持在此事件阻断
- **THEN** 钩子通过宿主原生机制明确拒绝，记录规则和原因，操作不继续

#### Scenario: 超时或缺失的钩子可能允许调用继续
- **WHEN** 用户验证某次已声称覆盖的调用，钩子超时、异常或在验证期内没有匹配回执
- **THEN** 系统展示已观察到的故障或结果未知，并明确显示宿主可能继续执行的限制，不将该结果报告为规则拒绝或成功校验
- **AND** 受控入口不能完成必要校验时停止受约束的操作并说明原因
