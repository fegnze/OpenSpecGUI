## ADDED Requirements

### Requirement: 桌面与受控 Agent 入口共用归档预检
桌面工作台和受控 Agent 归档入口 MUST 在归档写入前执行同一套只读预检。预检 SHALL 校验项目和 Change 身份、项目要求的官方 OpenSpec CLI 的兼容性、严格校验结果、增量规范同步状态，以及项目显式配置的其他归档门禁。对相同输入版本和项目规则，两个入口 MUST 得到相同的可归档判断和阻断原因。预检结果 MUST 关联所检查的项目、Change 和输入版本。任一入口发现输入变化后 MUST 重新预检，桌面端的原确认随预览失效。

#### Scenario: 相同输入得到相同预检结果
- **WHEN** 桌面工作台和受控 Agent 入口以同一项目、Change、CLI、规则及文件版本执行预检
- **THEN** 两个入口报告相同的增量规范同步状态及归档判定，失败时说明共同的阻断原因
- **AND** 预检过程不修改原项目的 Change、正式规范或归档目录

#### Scenario: 项目要求先完成增量规范同步
- **WHEN** 项目要求在归档前已同步正式规范，而预检发现该 Change 的增量规范尚未完整同步
- **THEN** 两个入口都阻止归档并说明待同步项，直到项目按既有工作流完成同步并重新通过预检

#### Scenario: 预检后的输入变化
- **WHEN** 预检通过后，相关文件、CLI 或项目归档规则在归档写入前发生变化
- **THEN** 相应入口要求重新预检，不允许使用旧结果执行写入

#### Scenario: 预检通过后由各入口继续归档
- **WHEN** 共同预检通过
- **THEN** 桌面端仍展示正式规范差异及目标路径并要求用户确认，通过原有受审阅归档事务执行
- **AND** 受控 Agent 入口仍按项目的官方 OPSX 流程和项目规则执行归档

## MODIFIED Requirements

### Requirement: 归档独立于 Agent 和会话
系统 SHALL 仅依据当前项目的持久化 OpenSpec 内容、适用的项目归档规则、兼容 CLI 的规则结果和用户的明确选择执行桌面归档，MUST NOT 要求 Agent 会话、聊天历史、模型凭证或模型服务。系统 MUST NOT 将任务完成或文档结构校验描述为实现验收。

#### Scenario: 没有 Agent 环境仍可归档
- **WHEN** 用户拥有兼容的本地 CLI 和有效 OpenSpec 文件，但未安装或登录任何 AI Agent
- **THEN** 用户仍可完成归档检查、预览、确认及执行

#### Scenario: 内容缺少明确的合并依据
- **WHEN** 增量规范不能按受支持规则产生通过校验的明确结果
- **THEN** 系统展示具体问题并保留原项目文件，允许用户通过自行选择的外部工具修正后重新检查

### Requirement: 归档前展示基于当前文件的检查结果
系统 SHALL 在用户确认之前展示选中 Change、项目、任务完成量、产物的完成或显式跳过状态、归档相关校验结果和目标目录。检查和预览 MUST NOT 修改原项目文件。缺失产物和未完成任务 SHALL 被明确列为待确认警告，项目预检规则明确要求的条件或 CLI 校验未通过时 MUST 阻止提交，且不能通过确认警告绕过。

#### Scenario: 任务全部完成
- **WHEN** 用户对任务全部完成的活跃 Change 发起归档检查
- **THEN** 系统继续检查产物和规范，并说明任务完成状态不代表已经完成实现验收

#### Scenario: 存在未完成任务或产物
- **WHEN** 任务存在未完成项，或者工作流声明的产物既未完成也未显式跳过
- **THEN** 系统列出相应任务数量或产物名称，且在用户明确接受这些警告前不允许提交
- **AND** 若这些项目违反项目要求的归档门禁，系统展示阻断原因并要求先修复

#### Scenario: 校验失败或用户取消预览
- **WHEN** 归档相关校验失败，或用户在确认写入前取消操作
- **THEN** 原项目的 Change、正式规范及归档记录保持不变
