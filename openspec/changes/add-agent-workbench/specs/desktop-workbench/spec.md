## ADDED Requirements

### Requirement: 区分项目导航和本机全局导航
系统 SHALL 在项目侧栏的「Agent 配置」区提供「能力绑定」和「钩子记录」。成员通过「能力绑定」浏览当前包收录的完整目录并管理当前项目与宿主的启用及配置。当前项目的 OpenSpec 可用时，系统 SHALL 在独立的「OpenSpec」分区平铺「执行台」「专项」「规范」「归档」。侧栏底部 SHALL 提供无需选择项目的本机「宿主接入」。成员导航 MUST NOT 提供独立的能力目录管理或全局能力接入入口。

#### Scenario: 首次打开已注册项目
- **WHEN** 用户首次打开一个 OpenSpec 项目或一个没有 OpenSpec 的普通 Git 项目
- **THEN** 系统分别打开「执行台」或「能力绑定」，并只在 OpenSpec 可用的项目显示 OpenSpec 分区

#### Scenario: 回到曾访问的项目
- **WHEN** 用户重新切回曾打开过项目页面的项目
- **THEN** 系统恢复该项目上次访问的可用项目页面，页面已不可用时回退到当前项目的可用入口

#### Scenario: 切换项目时停留在全局导航
- **WHEN** 用户在「宿主接入」中切换当前项目
- **THEN** 系统继续显示当前全局页面及本机范围数据，并更新项目导航配置

#### Scenario: 普通项目尚未绑定能力
- **WHEN** 用户打开一个没有 OpenSpec 且没有已启用能力的普通 Git 项目
- **THEN** 「能力绑定」显示完整目录，各条目在当前工作树与宿主下标为未启用，成员可直接选择所需条目

#### Scenario: 宿主尚未接入
- **WHEN** 当前项目的 OpenSpec 可读，但用户未接入 Agent 宿主
- **THEN** 用户仍可浏览该项目的提案、专项、规范和归档，归档可用性由归档自身的前置条件决定

#### Scenario: OpenSpec 加载中或刷新失败时管理能力
- **WHEN** 已登记项目仍有效，用户在 OpenSpec 首次加载或刷新失败期间打开「能力绑定」
- **THEN** 页面显示随包发布的能力目录和当前项目与宿主的绑定，用户也能访问本机「宿主接入」
- **AND** 返回 OpenSpec 页面可查看加载状态或错误并重试

### Requirement: 在工作台内更新应用与团队能力目录
工作台 SHALL 允许成员检查更新，显示当前版本、可用版本和准备状态，只为当前平台与架构准备通过发布签名校验的完整更新包。系统 SHALL 在更新准备完成后提供重启入口，重启后使用新包的应用及能力目录。

#### Scenario: 重启后在两个项目查看更新的能力
- **WHEN** 成员检查更新，等待适用架构的签名包准备完成并重启工作台
- **THEN** 两个项目的「能力绑定」均展示新发布版本的同一份目录，仍在包内的既有条目保留各自工作树与宿主的启用状态及兼容配置
- **AND** 新增条目在成员明确选择的工作树和宿主启用前维持未启用

#### Scenario: 更新包无法安全应用
- **WHEN** 找不到适用架构的更新包，或下载、签名校验、安装失败
- **THEN** 工作台显示失败原因，成员仍能使用此前成功安装的应用、能力目录和项目绑定

#### Scenario: 从旧产品名升级
- **WHEN** 用户退出 OpenSpec GUI 并首次打开 Agent Workbench
- **THEN** 应用使用新的桌面名称并可读取原有项目、绑定和个人授权
- **AND** 已登记且内容仍匹配的宿主入口可继续使用新应用，保留用户的其他宿主配置

### Requirement: 按需查看提案的 JSON 验收记录
系统 SHALL 在活跃与已归档提案的详情页按需展示该提案的 JSON 验收记录。打开项目、刷新执行台或进入详情时 MUST NOT 预读附件正文或预建附件清单。

#### Scenario: 展开某个提案的验收清单
- **WHEN** 用户主动展开「验收记录」
- **THEN** 工作台只列出所选提案的附件名称和文件信息，正文读取量为零

#### Scenario: 查看一份大型记录
- **WHEN** 用户选择一份 JSON 附件并继续翻阅
- **THEN** 工作台按次读取所选文件的一段文本，展示当前位置并允许继续阅读
- **AND** 附件消失、已被替换或项目切换后，旧读取不能展示为当前记录的正文

## MODIFIED Requirements

### Requirement: 支持刷新项目状态
系统 SHALL 允许用户手动刷新当前项目，并在应用重新获得焦点时检测需要更新的 OpenSpec 内容。

#### Scenario: 外部工具修改任务
- **WHEN** 外部编辑器修改当前提案任务且用户刷新工作台
- **THEN** 系统重新读取项目并展示最新完成量与进度

#### Scenario: 提案包含大型验收附件
- **WHEN** 有效项目的提案中附有大于正文扫描预算的 JSON 验收记录，且可索引的文档和配置仍在预算内
- **THEN** 首次打开与手动刷新均可载入当前提案、规范和归档
- **AND** 系统继续检测任务等索引输入的变化，附件内容的改动不会使整个工作区失效

### Requirement: 首页聚焦提案状态
系统 SHALL 在当前 OpenSpec 项目的「执行台」按状态组织并展示提案，且 MUST NOT 在该页面放置独立的待办任务列表或跨提案任务清单。

#### Scenario: 查看项目首页
- **WHEN** 用户打开当前 OpenSpec 项目的「执行台」
- **THEN** 页面以清晰状态分组展示提案名称、机器 ID、任务完成量、进度和更新时间

#### Scenario: 当前项目没有提案
- **WHEN** 当前项目的 OpenSpec 工作区不存在可展示提案
- **THEN** 「执行台」显示项目级空状态，并仍允许用户切换或管理项目

### Requirement: 项目切换不泄漏旧状态
系统 MUST 确保项目切换后的项目内容、选择、搜索和异步加载结果仅属于新当前项目。系统 MUST 使上一项目未提交的写入预览失效。

#### Scenario: 加载文档期间切换项目
- **WHEN** 用户在旧项目文档仍在加载时切换到新项目
- **THEN** 旧请求的结果不得覆盖新项目界面

#### Scenario: 从 OpenSpec 项目切换到普通项目
- **WHEN** 用户从 OpenSpec 文档、搜索结果或专项切换到没有 OpenSpec 的项目
- **THEN** 系统清除旧项目的文档、搜索和专项内容，打开新项目的可用页面
- **AND** 属于旧项目的归档计划不可提交，修改路由也无法访问新项目不具备的 OpenSpec 内容

#### Scenario: 加载能力绑定或钩子记录期间切换项目
- **WHEN** 用户在请求某项目的能力绑定或钩子记录期间切换项目
- **THEN** 旧项目的加载结果不会显示到新项目

### Requirement: 限制本地文件访问范围
系统 MUST 仅允许渲染界面通过明确命名并校验的操作读取当前注册项目中的 OpenSpec 内容、提交用户已审阅确认的 Change 归档，或执行工作台定义的能力与宿主管理操作。系统 MUST NOT 向渲染环境暴露任意文件系统、通用写入或进程执行能力。归档请求 MUST 绑定当前项目和预览结果。能力启用与配置写入 MUST 限于已审阅的项目或 worktree、目标宿主及包内条目。宿主安装写入 MUST 限于已审阅的本机目标宿主及安装项。独立 Initiative App MUST NOT 获得归档写入权限或能力与宿主管理权限。

#### Scenario: 请求当前项目之外的文档
- **WHEN** 渲染界面提交的文档路径解析到当前 OpenSpec 根目录之外
- **THEN** 系统拒绝请求且不返回目标文件内容

#### Scenario: Markdown 包含可执行内容
- **WHEN** 被读取的 Markdown 包含脚本、事件处理器或不受信任的外部资源
- **THEN** 系统以不可执行的安全内容呈现，不运行其中代码

#### Scenario: 提交伪造的归档范围
- **WHEN** 渲染界面提交任意文件路径、文件内容、执行命令或其他项目的归档计划
- **THEN** 系统拒绝请求，且只允许由主进程校验并保存的当前项目归档计划执行

#### Scenario: 独立专项应用请求归档
- **WHEN** 独立 Initiative App 或不受信任的页面尝试调用归档操作
- **THEN** 系统拒绝调用，且不扩大专项应用的既有权限

#### Scenario: 提交伪造的能力或宿主配置范围
- **WHEN** 调用方提交的目标宿主、项目范围或配置项不在用户审阅的预览内，或者独立 Initiative App 或不受信任的页面尝试调用配置写入操作
- **THEN** 系统拒绝调用，且不写入任何配置
