# 宿主与委派

仅在接入宿主、创建目标/任务或委派具体缺陷时阅读。本文件描述适配协议，不假定某个产品版本始终提供同一组工具。

## 同一实体的发现入口

技能实体包含 `SKILL.md`、脚本和按需资料。项目共享绑定与个人凭证不放进技能包。

- Codex：检查当前宿主报告的发现根。常见入口为 `.agents/skills/`；部分安装也使用 `~/.codex/skills/`。通过实际发现/调用验证，不能以目录存在当作已加载。
- Claude Code：常见项目入口为 `.claude/skills/`，个人入口为 `~/.claude/skills/`；本技能运行于主会话，不配置 `context: fork`。
- 工作台使用宿主个人级发现入口，使配置留在业务仓库外。接入时以工作台审阅的项目范围为准。发现入口指向同一技能实体。先检查已有同名入口，不覆盖旧技能、不复制第二份正文，不修改宿主其他配置。

完成接入后，从各宿主实际调用 `$feishu-defect-agent` 或该宿主提供的同名技能入口，确认技能正文与脚本来自同一包。Codex 的 `agents/openai.yaml` 是 UI 元数据，不能替代 Claude Code 的能力探测。

## 原生目标与任务

先检查当前会话真实暴露的工具及调用限制。工具名称、创建权限与恢复方式由宿主决定；不要虚构 `Target`、`TaskCreate`、`create_goal` 或跨宿主统一 API。

1. 新运行用 `choices` 获取近期配置，按 [启动前向导](binding.md#启动前向导) 在宿主中集中选择或自定义，再执行 `prepare`。准备就绪且选择未变时直接以新回执 `start`；准备未就绪前不创建宿主 Target。恢复已有运行用 `resume`，保留原主 `run_id`、选择和检查点。
2. 在当前用户授权及宿主规则允许时，创建或恢复一个运行目标，目标应明确本轮为「直接修复」或「仅排查」，并包含刷新节奏和手动暂停或停止条件。逐项任务也注明模式，排查结果不计作修复完成。
3. 为进入处理范围的缺陷建立逐项任务。业务稳定键为 `(project_key, work_item_type, issue_id)`；REOPEN 增加尝试记录，恢复同一运行复用已有任务。
4. 用 `host-link --input FILE` 保存宿主原生实体 ID 与本运行的映射。实际输入格式以该命令帮助为准；先核对实体已创建，不能只写映射就报告成功。

缺少原生目标或任务工具时，使用同一运行记录的降级展示并报告缺少哪项能力。工程已有 OPSX 计划时引用原计划；执行检查点只记录事实与回执，不复制工程计划或飞书业务状态。

空闲时保留原生 Target 为活动状态，并按 `next_refresh_at` 继续复查。用户手动暂停时保存检查点，手动停止时汇报停放项和未决事务。故障需要介入时保留恢复记录和实际结果。

## 具体缺陷的子任务

先由主 Agent 执行 `begin` 确认签名，再用 `worker` 准备任务材料。优先以精简或独立任务上下文派发；若宿主只提供继承上下文，说明真实行为，不把 fork 称作隔离。

交给子任务的最小材料：

- 技能目录、绑定和个人状态目录的运行时指针，主 `run_id` 与缺陷 ID。
- 指定仓库或 worktree、目标基线和本轮模式。「仅排查」只读查看并运行不会修改源码的检查，交回结论和证据或需 QA 补证的具体项；「直接修复」再指定允许修改的范围。
- 排查目的、相关依赖、工程必须执行的检查，以及证据保存位置。
- 返回结构与摘要预算；必要的来源详情由子任务通过 `detail` 按需读取。

任务提示只需说明本次具体目标，例如：

> 排查指定缺陷并在约定工程范围内完成可验证补丁。按指针读取必要详情和证据，遵循目标工程现有规则。主 Agent 已持有处理签名；你共用主运行 ID，不自行签名、提交、推送、发布、发消息或流转状态。交回结论、变更路径、实际验证及未决事项，日志保存文件。

不要要求每条缺陷并行。共享代码、依赖或交付通道时可以逐条串行委派；明确独立时再增加并发。工具权限、Bash 和 MCP 能力仍以宿主实际限制为准，提示词分工不构成强制只读沙箱。

## 子任务结果

通过 `worker-result --input FILE` 交回结构化结果，至少提供：

- `conclusion`：结论及是否已获得可审查补丁。
- `changed_paths`：实际变更路径；无修改时为空数组。
- `tests`：`{command, result, evidence?}` 数组，写实际执行及结果；未执行则为空，并在未决事项说明原因。
- `evidence`：可读取的证据位置。
- `unresolved`：仍需主 Agent 或人工处理的问题。
- `log_paths`：完整日志位置，主 Agent 只在必要范围读取。

例如，描述不足而尚未修改的任务可以返回：

```json
{
  "conclusion": "描述仅为空模板，暂无法确认复现与预期行为。",
  "changed_paths": [],
  "tests": [],
  "evidence": [],
  "unresolved": ["请 QA 补充复现步骤及环境；当前未启动代码修改或测试。"],
  "log_paths": []
}
```

默认结果预算 8192 字节，超出时提供短摘要和证据指针，不能把全文拆成多条消息。主 Agent 仍须审查实际差异和验证证据，再统一交付。

宿主压缩、续接或任务切换前，保存签名、工程基线、任务/原生 ID、未决副作用及下一步的紧凑记录。没有 subAgent 时采用分段调查并明确降级，不丢弃这些检查点。
