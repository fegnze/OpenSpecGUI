# OpenSpec GUI 桌面工作台设计规范

> 适用对象：OpenSpec GUI，以及规范管理、构建编排、CI、运维、本地开发工具等高信息密度桌面产品。
>
> 基线日期：2026-08-25。当前实现以 `src/renderer/styles.css` 和视觉回归基线为事实来源。

## 1. 设计定位

OpenSpec GUI 是面向开发者和技术团队的本地执行工作台。界面首先服务于扫描、判断和执行，不承担营销展示任务。

设计气质可以概括为：

- 安静：大面积中性背景，语义色只在需要判断时出现。
- 克制：少阴影、少圆角、少动画，不用装饰制造“高级感”。
- 精确：提案 ID、任务编号、时间、数量和百分比具有稳定的排版节奏。
- 高密度：同一视口内呈现足够多的项目状态，但不压缩文字可读性。
- 工具优先：页面重点始终是当前状态、下一步动作和异常，而不是品牌口号。

设计参数：

| 参数 | 值 | 含义 |
| --- | ---: | --- |
| `DESIGN_VARIANCE` | 3 | 结构稳定、低装饰变化 |
| `MOTION_INTENSITY` | 2 | 只保留反馈和状态动效 |
| `VISUAL_DENSITY` | 7 | 接近开发工具的高信息密度 |

### 1.1 核心原则

1. 先建立信息层级，再增加容器。
2. 用分隔线、留白和对齐组织内容，卡片只用于真正独立的对象。
3. 颜色表达语义，不表达装饰偏好。
4. 当前动作比历史信息更突出，异常比普通状态更容易发现。
5. 人类可读名称和机器可读 ID 同时保留，但使用不同字体层级。
6. 每个视图都覆盖加载、空、错误、禁用和完成状态。
7. 明暗主题共享同一套语义 token，不为每个组件单独配色。

## 2. 字体系统

### 2.1 字体栈

界面字体使用系统字体，保证 Electron 应用启动快、中文清晰，并与操作系统原生控件协调。

```css
--font-ui:
  -apple-system,
  BlinkMacSystemFont,
  "PingFang SC",
  "Hiragino Sans GB",
  "Microsoft YaHei UI",
  "Noto Sans CJK SC",
  sans-serif;

--font-mono:
  "SFMono-Regular",
  Menlo,
  "Cascadia Mono",
  Consolas,
  "Noto Sans Mono CJK SC",
  monospace;
```

不额外引入展示字体。`--font-display` 当前直接指向 `--font-ui`，标题通过字号、留白和位置建立层级，而不是依靠另一套字体制造差异。

### 2.2 字号层级

| Token | 大小 | 典型用途 |
| --- | ---: | --- |
| `--text-xs` | 11px | 更新时间、辅助说明、路径状态、卡片元数据 |
| `--text-sm` | 12px | 次级标签、状态来源、机器 ID、表头 |
| `--text-control` | 14px | 按钮、导航、提案名、任务正文 |
| `--text-body` | 15px | 普通正文、Markdown 正文 |
| `--text-section` | 17px | 页面内区块标题 |
| `--text-page` | 28px | 页面主标题 |

补充层级：

- 提案详情标题：24px。
- 文档二级标题：20px。
- 精确进度大数字：23-27px，使用等宽字体。
- 品牌名：15px。

### 2.3 字重、行高与字距

- 正文使用 `400`。
- 标题、按钮、状态和关键标签使用 `500`。
- 不依赖 `600` 或 `700` 建立层级，避免中文界面发黑。
- 全局正文行高为 `1.5`，任务文本为 `1.55`，Markdown 正文为 `1.75`。
- `letter-spacing` 固定为 `0`。不使用负字距，也不使用宽字距大写标签。
- 页面标题行高约 `1.25`，长标题允许自然换行，不截断核心含义。

### 2.4 等宽字体的使用边界

仅在需要逐位比较或识别机器信息时使用等宽字体：

- 提案 ID、项目路径和文档路径。
- 任务编号和阶段编号。
- 日期与时间。
- 数量、百分比和 `completed / total`。
- 代码、快捷键和原始 Markdown。

产品名称、提案标题、按钮文案和说明文字不使用等宽字体。

## 3. 颜色系统

### 3.1 中性表面

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--canvas` | `#f2f4f3` | `#0c1012` | 工作区底色 |
| `--surface` | `#fbfcfb` | `#141a1c` | 主要内容表面 |
| `--surface-raised` | `#f7f9f8` | `#1a2124` | 悬浮、表头、轻度抬升 |
| `--surface-muted` | `#eef2f0` | `#20282b` | 分组、输入、禁用轨道 |
| `--ink` | `#20292b` | `#e9eeec` | 主文字 |
| `--muted` | `#5d696b` | `#a5b0ad` | 次级文字 |
| `--line` | `#d5ddda` | `#303a3d` | 常规边界 |
| `--line-strong` | `#aebbb8` | `#465256` | 悬浮和强调边界 |
| `--code` | `#172022` | `#090c0d` | 代码和高对比提示 |
| `--code-text` | `#eff7f4` | `#eff7f4` | 代码和深色提示文字 |

侧栏在浅色和深色主题中都保持深色，作为稳定的应用框架，而不是内容区中的反色装饰带：

| Token | 值 |
| --- | --- |
| `--sidebar` | 浅色 `#111719`，深色 `#080b0c` |
| `--sidebar-raised` | `#192124` |
| `--sidebar-text` | `#f1f6f4` |
| `--sidebar-muted` | `#9caaa7` |

### 3.2 语义色

| 语义 | 浅色 | 深色 | 软背景 | 使用规则 |
| --- | --- | --- | --- | --- |
| 选择、当前、执行中 | `#2056b3` | `#91b5ff` | `#e5ecfb` / `#1c2c4a` | 焦点、选中、当前任务、执行中进度 |
| 成功、待归档 | `#08735f` | `#56d9b7` | `#dcefe9` / `#17382f` | 完成、健康、可归档 |
| 警告、推断 | `#9b5d08` | `#f4b652` | `#f5e9d3` / `#3f321b` | 文件推断、非阻塞诊断、搜索命中 |
| 错误、需要处理 | `#a73e32` | `#ff887c` | `#f5dfdb` / `#432521` | 缺失、异常、危险操作 |

规则：

- 一个状态至少同时使用文字或图标，不能只靠颜色。
- 蓝色是交互主色，不用于普通装饰。
- 绿色只表示成功或可继续的健康状态。
- 红色只表示真实风险、错误或需要处理。
- 不使用渐变、霓虹、彩色光晕或随机色卡片。
- 阴影使用带环境色的 `--shadow`，浅色为 `rgb(22 32 34 / 9%)`，深色为 `rgb(0 0 0 / 32%)`。

## 4. 间距与形状

### 4.1 间距网格

以 4px 为基础网格：

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 20px;
--space-6: 24px;
--space-8: 32px;
```

常见组合：

- 图标与文字：7-11px。
- 紧凑控件内边距：6-10px。
- 行内边距：7-13px。
- 组件间距：12-16px。
- 区块间距：20-32px。
- 宽桌面页面左右边距：`clamp(28px, 3vw, 44px)`。

### 4.2 圆角与边界

```css
--radius-control: 4px;
--radius-panel: 5px;
--radius-overlay: 6px;
```

- 常规边界为 1px。
- 状态卡片顶部线为 2px。
- 当前任务左侧线为 3px。
- 小型徽标和计数器可使用 3px，品牌标识和状态点可使用正圆。
- 不使用胶囊形按钮作为默认样式。
- 不使用 12px 以上的大圆角承载密集数据。
- 不在卡片内部继续嵌套装饰性卡片。

## 5. 应用布局

### 5.1 桌面壳层

应用使用固定高度的双列壳层：

```css
html,
body {
  height: 100%;
  overflow: hidden;
}

.app-shell {
  display: grid;
  grid-template-columns: 224px minmax(0, 1fr);
  height: 100%;
  overflow: hidden;
}

.workspace {
  min-height: 0;
  overflow-y: auto;
}
```

侧栏始终固定在窗口中，只有 `.workspace` 拥有纵向滚动。不要让 `body` 和工作区同时滚动，否则侧栏会跟随内容移动，sticky 工具栏也会失去正确的滚动容器。

### 5.2 尺寸基线

| 区域 | 尺寸 |
| --- | --- |
| 宽桌面侧栏 | 224px |
| 紧凑桌面侧栏 | 184px |
| 最小桌面图标轨道 | 72px |
| 顶部工具栏 | 最小 62px |
| 页面最大宽度 | 1540px |
| 页面内边距 | 顶 30px，左右 28-44px，底 46px |
| 搜索框 | 最大 520px，高 40px |
| 常规导航项 | 最小 42px |
| 常规命令按钮 | 最小 40px |
| 图标按钮 | 36px |

### 5.3 层级顺序

一个标准工作台页面按以下顺序组织：

1. 项目上下文和页面标题。
2. 内容刷新状态或关键操作。
3. 状态摘要或视图切换。
4. 当前动作、异常或主要对象列表。
5. 次级上下文和文档入口。

不要在页面顶部放营销式 hero、欢迎卡片或功能说明。用户进入工具后应立即看到可操作内容。

## 6. 核心组件规范

### 6.1 品牌与侧栏

- 产品标识在完整侧栏中为 34px，在图标轨道中保持相同视觉重量。
- 产品标识必须使用透明背景资源，不得带白色底板或截图棋盘格。
- 品牌名 15px / 500，副标题 11px / 400。
- 主导航仅保留一级工作区。当前结构为“执行台、规范、归档”。
- 图标来自同一套 Lucide 线性图标，常用尺寸 14-18px，保持一致的描边风格。
- 当前导航使用深色抬升表面、细边框和绿色图标，不使用大面积高饱和填充。
- 图标轨道隐藏文字时必须保留 `aria-label` 和悬浮说明。

### 6.2 项目选择器

项目选择不是普通枚举，因此使用自定义 listbox，而不是原生 `select`：

- 触发器最小高度 58px，同时展示目录名和连接状态。
- 菜单行最小高度 48px，支持项目名、健康状态和失效状态。
- 当前项、可切换项和失效项必须有不同反馈。
- 支持方向键、Home、End、Enter 和 Escape。
- 菜单打开后保持在侧栏层级内，最大高度 280px，超出时仅菜单滚动。
- 项目显示名默认保持原目录名，不生成缩写、大小写或连字符变体。

只有主题等简单、短选项集合可以继续使用原生 `select`。

### 6.3 顶部工具栏

- 工具栏在 `.workspace` 中使用 `position: sticky; top: 0`。
- 左侧为全局搜索，右侧为主题和刷新等全局命令。
- 最小窗口时增加项目入口，弥补侧栏项目选择器被折叠后的功能缺口。
- 熟悉的命令优先用图标按钮，并提供 tooltip 和可访问名称。
- 工具栏属于窗口拖动区域，所有按钮、输入和选择控件必须声明 `-webkit-app-region: no-drag`。

### 6.4 状态摘要

状态摘要使用横向分隔带，而不是四张浮动统计卡：

- 四列顺序固定为“活跃、进行中、待归档、需要处理”。
- 当前项使用 2px 蓝色底线。
- 数量使用 23px 等宽字体，标签 12px，说明 11px。
- 点击后必须直接显示对应提案列表，并同步下方筛选状态。
- 摘要区域只表达状态和数量，不加入趋势图或装饰图表。

### 6.5 执行状态分栏

执行台首页按“进行中、待归档、需要处理”形成三列：

- 列容器使用 muted surface 和 1px 边界。
- 列头最小高度 70px，包含语义图标、名称、说明和数量。
- 卡片之间间距 8px，列之间间距 14px。
- 空列保留最小高度和明确空状态，防止布局跳变。
- 卡片点击进入详情，复制按钮只复制提案 ID，不触发路由。

### 6.6 提案卡片

提案卡片最小高度 140px，结构固定为：

1. 状态和更新时间。
2. 人类可读标题和机器 ID。
3. 精确任务数量、百分比和分段进度条。
4. 独立的复制按钮。

卡片顶部状态线使用蓝、绿、红三种语义色。悬浮时只加强边界并增加轻阴影，不移动卡片，不放大卡片。

复制按钮使用熟悉的 copy 图标，视觉尺寸 30px，点击成功后短暂切换为绿色。按钮必须有完整 `aria-label` 和 tooltip。

### 6.7 进度条

总体进度必须同时包含：

- `completed / total`。
- 百分比。
- 10 段分段进度条。
- `role="progressbar"`、`aria-valuemin`、`aria-valuemax`、`aria-valuenow` 和可读的 `aria-valuetext`。

视觉规格：

- 高度 6px，阶段标题中的紧凑版本为 5px。
- 段间距 3px，紧凑版本为 2px。
- 未完成段使用 `--surface-muted`。
- 执行中使用蓝色，完成使用绿色，需要处理使用红色。
- 最后一段支持 10% 粒度的部分填充，避免 91% 和 99% 显示为同一状态。

实现时 `.progress-bar` 必须保持 CSS Grid。不要用宽泛的后代选择器给其中所有 `span` 设置 `display: flex`，这会破坏分段轨道。

### 6.8 提案详情与任务

- 标题区同时展示状态、提案 ID、复制操作和总体进度。
- “当前任务”使用有色软背景和 3px 左侧线，是页面最优先的行动提示。
- 任务阶段使用分隔行组织，不把每个任务包装为独立卡片。
- 阶段标题最小高度 44px，任务行宽桌面最小高度 44px。
- 已完成任务使用绿色勾选和弱化文字。
- 当前任务使用蓝色背景、左侧线和明确“当前”文字。
- 键盘定位目标使用 2px 焦点边界，不只依赖背景色。
- 宽桌面上下文栏为 280px；低于 1280px 时移到主任务流下方。

### 6.9 文档阅读器

- 正文最大宽度 780px，正文 15px / 1.75。
- 目录栏宽度 180-220px，使用左侧分隔线，不使用独立浮动卡片。
- 文档 `h2` 用上分隔线建立章节，`h3` 用绿色左侧线建立次级层级。
- 行内代码使用 muted surface，代码块使用 code surface。
- 表格最小宽度 540px，只允许表格容器横向滚动。
- 长链接、路径和机器 ID 使用 `overflow-wrap: anywhere`。
- 阅读和原文使用 segmented control，不创建两个独立页面。

### 6.10 对话框、反馈与状态

- 对话框最大宽度 680px，圆角 6px，内容过长时对话框内部滚动。
- Toast 固定在窗口底部中央，只用于短暂反馈，不承载需要用户决策的错误。
- 加载状态使用与最终内容接近的骨架行，不使用无上下文的圆形 spinner。
- 空状态说明“当前没有什么”，避免营销式文案。
- 错误状态就地展示原因和恢复操作。

## 7. 交互与动效

### 7.1 状态反馈

- Hover：改变文字、表面或边界，持续 120ms。
- Active：按钮向下移动 1px，表达按压反馈。
- 同页切换和折叠：最多 180ms。
- Focus：`2px solid var(--blue)`，外偏移 2px。
- Disabled：透明度降到 0.5，光标恢复默认。

### 7.2 动效边界

允许：

- 刷新图标旋转。
- 骨架加载呼吸。
- 菜单箭头旋转。
- 颜色、边界、透明度和轻微按压反馈。

不允许：

- 页面入场编排。
- 滚动劫持、视差和自动跑马灯。
- 卡片漂浮、磁吸按钮和循环装饰。
- 为普通列表引入 GSAP 或大型动画依赖。

在 `prefers-reduced-motion: reduce` 下关闭动画、平滑滚动和过渡。

## 8. 明暗主题

- 根节点使用 `color-scheme: light dark`，主题 token 使用 `light-dark()`。
- 提供“跟随系统、浅色、深色”三种模式。
- 同一主题内不按区块随意反色。
- 深色侧栏是持久应用框架，可以在浅色内容主题中保留。
- 组件只引用语义 token，不直接判断主题并写两份样式。
- 深色模式不能简单反转颜色，需要单独控制边界、阴影和 muted surface 的对比。
- 品牌标识必须在两种主题和 34px 小尺寸下仍然清楚。

## 9. 响应式与最小窗口

| 范围 | 布局 |
| --- | --- |
| `>= 1280px` | 224px 完整侧栏，详情主区与 280px 上下文栏并列 |
| `960-1279px` | 184px 紧凑侧栏，详情上下文移到主内容下方 |
| `<= 959px` | 72px 图标轨道，正文单栏优先，工具栏显示项目入口 |

当前最小视觉验收尺寸为 820x640。

规则：

- 不随视口宽度缩放字体。
- 不允许页面级横向滚动。
- 三列执行状态在最小窗口中改为组件内横向滚动，列宽约为可用区的 76%，露出下一列作为可滚动提示。
- 状态摘要仍保持四列，缩短辅助信息而不是折成杂乱的多行卡片。
- 详情在窄窗口中先展示当前任务，再展示次级上下文。
- 表格、代码块、选项菜单和分栏可以拥有自己的滚动容器。
- 文本必须换行或省略，不能与图标、计数和操作按钮重叠。

## 10. 文案与信息架构

- 中文优先，技术实体保留原始英文和机器 ID。
- 页面标题使用对象或工作区名称，例如“当前执行”“规范”“归档”。
- 命令使用动词和对象，例如“定位任务”“复制路径”“刷新项目内容”。
- 状态词统一使用“进行中、待归档、需要处理”。不要在不同视图创造同义词。
- 提案标题承担解释，提案 ID 承担检索和复制。
- 项目名保持目录原名，不擅自美化、翻译或生成变体。
- 界面内不放功能介绍、快捷键教学或营销价值陈述。
- 时间、数量和来源要明确，避免“最近”“很多”“已同步”等模糊表达。

## 11. 无障碍要求

- 正文对比度至少满足 WCAG AA 4.5:1，大文字至少 3:1。
- 所有键盘可操作元素都有清晰的 `:focus-visible`。
- 图标按钮提供 `aria-label`，陌生图标提供 tooltip。
- 当前导航使用 `aria-current`，筛选使用 `aria-pressed`，选项使用 `aria-selected`。
- 项目菜单实现 listbox 键盘模型和 Escape 返回焦点。
- 状态同时提供图标和文字。
- 进度条同时提供数字和无障碍属性。
- 对话框关联标题，并管理打开和关闭后的焦点。
- 动态状态使用合适的 `aria-live`，但避免频繁播报静态列表。
- 125% 页面缩放下仍不得出现页面级横向滚动或控件重叠。

## 13. 适用边界

这套规范适合直接复用到：

- 本地开发工具和桌面工作台。
- 规范、任务、构建、发布和 CI 管理工具。
- 需要同时展示人类名称与机器标识的技术产品。
- 以扫描、筛选、诊断和执行为主的内部工具。

以下情况应调整：

- 面向普通消费者时，提高正文和控件尺寸，降低等宽字体和数据密度。
- 大型企业产品已经采用 Fluent、Carbon、Atlassian Design System 或 Primer 时，应使用其官方组件和 token，不要混搭两套系统。
- 触屏为主时，把主要点击区域提高到至少 44px。
- 数据分析产品需要大量图表时，保留本规范的层级和语义色原则，但另建图表 token。
- 营销站、品牌展示页和内容网站不应套用这套工作台布局。

## 14. 禁止项

- 不使用紫蓝渐变、玻璃拟态、发光边框和装饰性背景球。
- 不使用超大标题、hero、品牌宣言或欢迎卡片占据首屏。
- 不把每个区块和每条数据都装进圆角卡片。
- 不混用多套图标或手绘功能图标。
- 不在状态色之外随意增加强调色。
- 不把机器 ID 当标题，也不隐藏机器 ID。
- 不只显示百分比而移除整体进度条。
- 不让侧栏随正文滚动。
- 不让复制、刷新等次级命令改变当前路由。
- 不为低动效工具引入 GSAP、滚动编排或持续动画。

## 15. 交付前检查

### 视觉

- [ ] 浅色和深色主题使用同一套语义层级。
- [ ] 页面标题、当前动作和异常的优先级清楚。
- [ ] 结构容器只使用 4px、5px、6px 三档圆角，徽标和正圆图形遵循已定义例外。
- [ ] 卡片、分隔线和阴影没有过度使用。
- [ ] 提案卡片同时显示精确数量、百分比和进度条。
- [ ] 机器信息均使用等宽字体，普通文案未滥用等宽字体。

### 交互

- [ ] 所有按钮都有 hover、active、focus-visible 和 disabled 状态。
- [ ] 图标按钮有可访问名称和必要的 tooltip。
- [ ] 筛选点击后直接显示对应内容。
- [ ] 复制操作不触发父级点击或路由。
- [ ] 加载、空、错误和完成状态都已覆盖。

### 布局

- [ ] 1440x930、1180x760 和 820x640 均无页面级横向滚动。
- [ ] 侧栏固定，只有工作区纵向滚动。
- [ ] 最小窗口仍可访问项目、导航、搜索、筛选和首个主要对象。
- [ ] 长标题、路径、代码块和表格不会遮挡相邻控件。
- [ ] 125% 缩放下没有重叠或不可达内容。

### 无障碍与回归

- [ ] 颜色不是任何状态的唯一表达方式。
- [ ] 键盘可以完成项目切换、筛选、进入详情和返回。
- [ ] `prefers-reduced-motion` 下没有非必要动画。
- [ ] 自动无障碍扫描无严重和关键问题。
- [ ] 宽桌面、紧凑桌面、最小桌面和深色主题都有视觉回归基线。
